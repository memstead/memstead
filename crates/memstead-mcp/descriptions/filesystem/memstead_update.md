Update an existing entity in the filesystem-mem workspace. `expected_hash` (from a previous memstead_entity read) is required for any update that changes content, and may be OMITTED for an anchors-only update (anchors / anchors_unset and nothing else), since anchors sit outside `_hash` — mismatch returns code HASH_MISMATCH with details.current carrying the live hash. An anchor naming a stored (artifact, grain, class) triple replaces the row: hash-less for the next verify to backfill when a field differs or the update also changed content, a no-op when it restates the row; `anchors_changed` on the response says which. This surface honours `sections` (replace) + `sections_unset` (remove heading and body; no-op on an absent key, refuses on a REQUIRED section) + `metadata` (set) + `metadata_unset` + `declare_relations` + `relations_unset`. The mem-repo `append_sections` / `patch_sections` / `dry_run` shapes are NOT implemented here: passing a non-empty `append_sections` / `patch_sections`, or `dry_run: true`, is REFUSED up front with `UNSUPPORTED_PARAM` (`details.params` names them), never silently ignored — an agent that patches is told its patch was dropped instead of believing it applied. Omit them, or use the unified engine (mem-repo MCP / CLI) which honours all three. The entity's type is not updatable here (the reserved identity triple): change it with `memstead_retype`, which re-validates sections, metadata and every edge against the target type.
