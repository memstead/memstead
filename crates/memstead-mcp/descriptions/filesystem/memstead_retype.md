Modify an entity's type in place. The id, file path, and every incoming edge stay. The existing sections and metadata are validated against the target type with a report-all refusal (`UNKNOWN_SECTION` with `details.target_sections` and a `details.proposed_section_map`, `MISSING_REQUIRED_SECTION`, metadata codes, block-tier constraints), and every incoming and outgoing edge is re-checked against the target type's relationship pins (`INVALID_REL_SHAPE`, each edge listed); mixed problem classes carry `RETYPE_REFUSED` with `details.problems`. `section_map` renames section keys on the way and `drop_metadata` lets go of fields the target does not declare; nothing is moved or dropped silently. `expected_hash` is required unless `dry_run`, which validates and returns `prospective_hash` without writing. Response carries `old_type`, `new_type`, `_hash`, `sections_renamed`, `edges_rechecked`, `write_id` (an identity, never a change cursor), and `checks_stale` with a `staleness_note`: the content hash moved, so check records and derivation baselines on the entity are stale.
