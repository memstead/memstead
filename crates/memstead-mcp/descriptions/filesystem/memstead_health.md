Return the workspace's health summary: orphans, stubs, missing required fields, stale entities. Same JSON shape as the mem-repo `memstead_health`, across every mounted mem. Pass `mem` to scope counts, scans, and include sections to one visible mem; a name matching no visible mem refuses `UNKNOWN_MEM` (never a clean full report); omitted serves the engine-wide sweep. `include` accepts the shared health key set. `ledger` matters most here: this surface serves FOLDER mems, whose drift cursor is their own engine-written change ledger, so edits made to their files by anything else go undetected (health warns `OUT_OF_BAND_EDITS_UNDETECTED`) — `ledger` reconciles the ledger against the files on demand, per mem, read-only. The lean surface also dispatches `dangling_links` (mem-repo response shape: `{kind, from, target_id, target_path, section}`, `kind` naming which of the three) and validates every key against the allowed set, emitting `UNKNOWN_INCLUDE_KEY` on the response's `warnings[]` for typos. `conformance` / `integrity` are dispatched too: `conformance` lints every entity against the effective schema (the pin, or `target_schema` when given) into a `findings` array of `{id, axis, code, detail}` with write-time typed codes; `integrity` adds the consistency axis (ORPHAN_STUB; CROSS_MEM_EDGE_UNGRANTED, an edge the grants no longer permit; DANGLING_LINK_TARGET_MISSING; DANGLING_LINK_NOT_RELATED; DANGLING_RELATION_TARGET_MISSING) to the same list; `anchors` adds per-mem counts of the standalone anchor-verification states (resolved/drifted/recheck/unresolvable = artifact gone/unobserved = unmeasured), plus `dangling` (row naming a gone entity, its own condition and not a state), `entity_end_unreconciled`, and `population`/`fully_adjudicated`: the figures never travel without what they were computed over. `constraints` lists standing declared-constraint violations with `severity`. Other detail keys (`orphans`, `stubs`, …) are accepted but the v1 surface returns the full report regardless — narrowing is a follow-up.
