Per-mem change feed. **`since` is backend-specific and NEVER a mutation's `write_id`** (a folder mem refuses that token with `INVALID_CURSOR`). Git-branch mem: `since` is a commit SHA of the mem's own history — the `head` a prior call returned, or the empty-tree hash `4b825dc642cb6eb9a060e54bf8d69288fbee4904` for a first sync. Folder mem: `since` is an RFC3339 timestamp — the `head` a prior call returned (the timestamp of the last ledger entry), or empty for a first sync. Returns a flat list of entity-level events — each event's `action` is one of `added`, `updated`, `removed`, `renamed`. Non-`removed` events carry `title` and `entity_type` ; a `removed` event carries neither key. Engine-authored renames pair via commit-note provenance (`memstead: rename <old> → <new>`), composed across rename chains. Non-engine renames (`git mv`) fall back to a content-similarity scorer (default 0.6, tunable via `rename_similarity` in [0.1, 1.0]), capped at 1000 rewrite pairs per diff. Either path surfaces as one `renamed` event with `from_id` and `to_id`, never a removed+added pair; a folder mem pairs its ledger's rename row with the id that vanished, and an entity added and renamed inside one window arrives once, as `added` under its final id. Out-of-range `rename_similarity` refuses `INVALID_INPUT` naming `details.allowed_range` and `details.requested`. `head` is the next polling cursor on both backends: the HEAD SHA of a git-branch mem, the last ledger timestamp of a folder mem. No pagination — every qualifying commit ships in one response. Pass `include_notes: true` to fold per-commit agent-notes (`notes[]`) and `memstead_ref` into the response. A `since` unknown, malformed or outside the mem's own history (another mem's commit, a replaced history) returns `INVALID_CURSOR` with `details.mem` and `details.since`; re-seed from the empty-tree hash. `mem_changed` notices of ≤50 changes (`mode: detailed`) add each entity's newest write: `identity`, `note`, absent when undeclared.
