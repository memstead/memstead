Return the review brief of a fork against the mem it was forked from: the entity-level three-way picture the owner reads before merging, and the disposition file to fill. Read-only: nothing is written anywhere. `fork` names a mounted git-branch mem whose config records its origin (`memstead mem fork` writes it); its changes are read against its base (the fork commit, or the ancestor for an older fork) and the source mem's branch tip at call time, and the response names `ancestor`, `base`, `fork_tip` and `target_tip` so a merge can pin them. `entries[]` carries one entry per entity the fork touched, sorted by `slug`, each with `status` (`added`, `modified`, `deleted`, `renamed`), `fork_delta` (the sections and metadata that differ against the base; a self-link the fork commit retargeted is never a difference), `referrers` (the target's), `anchors` (the fork's rows: artifact, grain, class, span, last recorded state; nothing is observed), `precheck` (would the body pass the target's write gate: `clean`, `failed` with the gate's typed codes, or `not_run`; never a content judgement), `conflict` where the target modified, deleted or created the same entity since the ancestor (with the three bodies), and `re_proposal` marks where the target's proposal record already rejected the same content hash or id. `dispositions` is the skeleton keyed by slug: empty `disposition` and `reason`, and the accepted values `adopt`, `adopt_with_changes`, `reject` (no `adopt` on a conflict); `description` is the empty slot for the proposal in the owner's words, recorded by the merge. The text channel carries the markdown rendering, `structured_content` the JSON. Refusal codes: `INVALID_INPUT` (the mem records no origin, or a side is not git-backed), `UNKNOWN_MEM` (the fork, or its source, is not mounted), `UNKNOWN_REF` (a recorded sha no longer resolves). The merge is CLI-only (`memstead proposal merge`).
