# Code-map preparation hashes a heuristic interface digest and closes the tree grain for code sources

## Decision
We chose to realize the preparation registry's code-map flavour (`code-map`, touchpoint A on path-shaped sources) as a heuristic, language-family-aware **interface digest**: comments are stripped, and of what remains only declaration lines survive (imports, exports and re-exports, functions, classes, interfaces, types, enums, top-level bindings, Rust items and struct fields, class and object member signatures one and two levels in, Python imports, `def`/`class` lines, decorators and upper-case module constants), each joined across a multi-line signature, array or import list, cut at its body's opening brace (Allman-style or not), and normalized (whitespace collapsed, no space next to punctuation, trailing commas and semicolons dropped, double quotes read as single, quoted keys and parenthesized lone arrow parameters read bare, a scalar property value reduced to its key); a binding whose value is not a function (`const`/`let`/`var`, a class field, a Rust `pub const`/`pub static`/`pub type` item, CommonJS `exports.x`/`module.exports`) is cut right after its `=` at any depth, a default export that is not a function or object literal right after `default`, and the value's lines are skipped whole until every brace, bracket or parenthesis it opened closes; an arrow's expression body is cut right after its `=>`; an enum member keeps its explicit value and an interface's method member (a signature with a return type and no body) is kept, judged on the joined signature when a formatter wrapped its parameters; a destructuring pattern a formatter wrapped (`const {`, `let [`) joins across its brackets before the binding rule cuts the value, so its names are interface in both forms; a member line kept only as a signature must open a body once joined, so a call statement wrapped across lines never enters the digest; and a declaration joins its continuation lines across open parentheses, brackets, generics, list braces, a line-final `=` or `:` and formatter-led operators (`|`, `.`, `?`, `:`, `+`, `&`) but never past a body brace (an import or export list's brace is a list, not a body), so a value's wrapping, operators and literal shape are body, a callback's body inside a call's parentheses is body, and a signature's wrapping is invisible; a Vue (or Svelte) single-file component contributes its script block only; JSON is its canonical compact form; every other file is taken whole. The family is chosen by file extension, and the digest is hashed through the same minimal canonicalization every prepared form uses. A `file` or `span` anchor on a code-map source hashes the digest; a `tree` anchor hashes the code map of every scoped file under it (one line per file: digest hash and path, path order), which closes the tree grain's recorded-but-unhashed residue for code sources. The remainder is stated, not closed: a tree anchor on a source without a code map stays unhashed and resolves `recheck`. Write-time `content` is hashed through the anchor's source's preparation at the engine seam, so the hash an agent's write records is the hash a later observation computes, and the build brief tells the agent when a source's anchors hash a prepared form (leave `hash` empty or pass `content`; never compute it by hand). `PREPARATION_IMPL_VERSION` bumps to 3.

## Context
The design `engineering--one-preparation-slot-three-flavours-two-engine-touchpoints` binds the third flavour to the WOENENN field need (the 2026-08-18 needs statement, item 3: cut per-iteration ingest cost; acceptance case a corpus of about 200 scoped files) and to a skepticism check: an agent can build a code map itself, so the engine-owned slot earns its place only through the prepared-hash and stability drift contract. Before this decision every path-grain anchor hashed the file's bytes, so any edit anywhere in a file drifted every dependent entity, and a tree anchor never carried a hash at all (recorded, never observed). The registry ([[engineering--the-preparation-registry-is-engine-owned-and-its-entity-flavour-hashes-the-load-bearing-sections]]) and its per-anchor observation site were in place; this decision adds the path-grain prepared form. Measured on the WOENENN main-app binding on 2026-08-24 (214 scoped files: 141 JS, 70 Vue, 2 JSON, 1 Python; 1.8 MB): the digest is 4.6% of the raw bytes (458,417 estimated tokens raw against 21,234 digest; JS 5.5%, Vue 3.3%, Python 2.7%, JSON 80.2%); over the last 300 commits, 176 touched a scoped file's content and 82 of those changed an interface; of 424 scoped file changes, 172 changed an interface and 252 were body-only, so 59.4% of file changes would not drift a code-map anchor. The digest was refined six times under grading before these numbers were taken (formatting inside declarations normalized away; wrapped import, export and array lists joined, which made member changes inside wrapped lists visible; every top-level binding's value cut as body; arrow expression bodies cut, CommonJS export values cut, wrapped call statements dropped, operator-led and generic wraps joined; then bindings cut at any depth including `pub` items and class fields, values wrapped after `=` and types after `:` joined, no join past a body brace so callback bodies stay body, bracket-opened values skipped, and interface method members, enum members with their values and destructuring patterns kept); the earlier readings of 59.7%, 58.5%, 58.0%, 59.2% at 6.6% and 59.2% at 6.2% were replaced by this one. The engine surfaces changed: [[engine--anchor-primitive]] and [[engine--pipeline]].

## Consequences
- An entity anchored on a code file (or a tree of them) under `code-map` is re-examined only when an interface changes: measured on the field corpus, three of five file changes stop producing drift findings, and a verify pass over an interface-stable tree is quiet.
- The digest is heuristic. What it normalizes away, pinned: comments anywhere, indentation, blank lines, brace style (Allman and K&R members digest alike), comma spacing, trailing commas (in lists, objects and generics), semicolons, quote style, quoted keys, parentheses around a lone arrow parameter (top level and on property arrows), black's parenthesized import lists, a leading `|` on a wrapped union type, and every formatter wrap the pins enumerate: a signature, array, import or export list, a generic list, an arrow's expression body, a value broken onto the line after its `=` or a type after its `:`, a typed member's wrapped parameter list, a wrapped destructuring pattern, a ternary or member chain or `+` chain in a value, a call statement inside a body. What it treats as body, pinned: function bodies, every binding's value at any depth whatever its shape (a ternary or binary expression wrapped by a formatter, a member chain, a `({`-opened literal and its members, a `[`-opened list, a one-line literal, a class field's initializer, a Rust `pub const` value), a callback's body inside a call's parentheses, a default export's non-function value, a Python module constant's value, and a scalar property value inside an `export default {` or class body (`name: 'Auth'` keeps only `name:`). What it keeps, pinned: an interface's members (typed properties and method signatures with their return types), an enum's members with their explicit values, a Rust struct's field names and types, a destructured require or import pattern's names. Recorded blind spots, all under-drift: an exported constant whose value IS the interface (a version number, a limit) never drifts, because values are body; a property two levels down inside an expanded literal is invisible; brace counting inside string literals can shift the depth heuristic; a regex literal containing a quote can swallow a line; template-only Vue components have an empty map; languages outside the recognized families are taken whole (whole-file hashing, as before). Each is a property of the registry entry, improvable without touching the contract, and a precise parser is a later registry entry, not a redesign.
- Sources declaring no preparation observe exactly as before: whole-file hashing for `file`/`span`, no hash for `tree`.
- `content` on an anchor write is now preparation-aware for every flavour that prepares path grains (code-map, dated-entries units); a unit key the supplied content does not yield refuses (`UnitAbsentFromContent`).
- Every binding's `hash(D)` changes again (impl version 3): prior findings are superseded by construction and re-derived by the next verify.
- The measurement harness (`measure_code_map_over_corpus`, an ignored env-gated test) can be re-run on any corpus to re-check the ratio before a source adopts the flavour.

## Options

- A real parser per language (tree-sitter or per-language grammars): rejected for the first entry. It adds a dependency tree the engine does not otherwise carry, and the drift contract needs an exact and stable digest more than a semantically complete one; the heuristic is deterministic, dependency-free, and its blind spots are named. A grammar-backed digest is a later registry entry under the same identifier semantics.
- Deliver the digest to the agent as the ingest payload (read the map instead of the file): rejected as the criterion for this flavour. The skepticism check says the engine's value is the drift contract, not a summary an agent could produce itself; the digest is what anchors hash, and the brief tells the agent that, while the agent keeps reading source on its own terms.
- Close the tree grain for every source by hashing a tree's raw file contents: rejected. It would change every existing tree anchor's semantics (from recheck to drift on any byte), cost a full walk and hash per observation on large trees for sources that never asked for it, and cut across the plan-01 complement that undeclaring sources stay byte-for-byte as before. Closing it under `code-map` only, and stating the remainder, keeps the contract honest.
- Hash the interface digest for the `tree` grain by concatenating the files' digests: rejected in favour of one line per file (hash and path). A file moving or being renamed then changes the map even when its interface is identical, which is the truthful reading of a tree's shape changing.
