Three things go wrong. First, the source moves: files the mem describes are edited, added, or deleted. Second, entities age or lose their footing: a claim sits untouched past a threshold, an edge derived from another entity no longer matches that entity's current content, a link points at nothing, or a recorded verification no longer applies because the entity changed. Third, the engine's own in-memory picture falls behind the mem repository when another process commits to it.

Noticing is deterministic and engine-side. Each entity written from a source carries anchors: the artifact path, a grain, a provenance class, a version, and a hash over the prepared artifact. Verification re-observes every anchor and classifies it as resolves, drifted (hash differs on a stable medium), recheck (hash unavailable or medium unstable), or orphaned (artifact gone) (anchor.rs `resolve_anchor`, `AnchorState`; query.rs `mem_anchors_resolved`). Source movement is detected per binding by comparing a stored baseline token against the source's current state: a git commit diff, a graph snapshot diff, or a per-file mtime/size digest that also catches deletions (cursor.rs `compute_source_cursor`, `source_moved_since`; change_detection.rs `diff_stat_maps`). Health separately reports entities older than the schema's `staleness_threshold_days` (deferring to anchor state when one exists), dangling links, and stale derivation edges (health.rs, `health_stale_derivations_axis`, stale_anchor_clock.rs). Check records go `check_stale` once the content hash moves (check.rs). Every operation probes the mem's head and reloads if it advanced, emitting a `MemReloaded` warning (drift.rs `reload_if_stale`).

What it does about it is deliberately limited. Verify writes durable findings (drifted, uncovered, unresolvable-anchor, unanchored-mention, queued-for-adjudication) and a fidelity report, but never touches an entity (findings.rs `verify_binding`, `FindingClass`; report.rs). The sync brief presents the changed slice, open findings, and prune proposals to an agent, which performs the repairs through the normal mutation surface; deletions are proposed, never automatic, and authored entities are never prune targets (brief.rs `render_sync_brief`; prune.rs). Baselines advance only when the agent records dispositions for the whole slice (advance.rs `advance_baseline`). A loop rotation picks due bindings with backoff (selection.rs). Whether a scheduled full walk occurs depends on `full_resync_every` (findings.rs `schedule_full_resync`). The engine never repairs content on its own.
