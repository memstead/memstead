Four things go wrong. An entity keeps describing a file that has since changed (drift); a file appears that no entity describes (uncovered); a file is deleted while its entity lives on (a prune candidate); and a mem is edited from outside so a running engine's cache is behind the disk. Memstead treats each separately and never repairs content on its own.

The load-bearing primitive is the anchor: a durable sidecar row tying an entity to a source artifact at a grain (span, file, tree, url, entity) with a hash over the prepared form, written in the same commit as the entity (engine--anchor-primitive). Nothing is stamped as fresh; staleness is computed by re-hashing. `memstead verify-anchors --mem <name>` reports per anchor `resolves`, `drifted`, `recheck` (unstable hash or missing baseline), `unresolvable` (artifact gone) or `unobserved`, with the population it measured so a count is never read as health (engine--standalone-anchor-verification-surface). The `memstead_health` tool folds this in: its `stale` axis reads anchored entities by anchor state and unanchored ones by a per-type day threshold, and opt-in axes cover dangling links, orphans and derivation baselines (engine--graph-health-report-surface, engine--derivation-staleness-baselines).

For a mem built from a source by a binding, change detection targets what moved since the last baseline (git commits, or a per-file mtime/size digest that catches deletions) and renders it as a changed slice in a sync brief; a no-signal case is named rather than shown as empty (engine--source-change-detection-and-deny-path-verdicts, engine--run-brief-assembly). `projection verify` measures coverage, accuracy and freshness, records durable findings, and mutates no entity (engine--projection-verify-and-findings-store). Deleted files become prune proposals, never automatic deletions; where a git base is retrievable it can separate a clean removal from a model-side edit (engine--prune-proposals). The repair itself is the agent's: it works the slice, records a disposition per artifact, and the `#synced` baseline advances only when nothing unexamined remains (engine--projection-advance-and-the-disposition-gate).

Externally edited mems are handled automatically: before every operation the engine probes each mount's head, reloads what moved, and flags `MEM_RELOADED` (engine--reload-before-operation-coherence). I could not verify how the loop scheduling behaves end to end beyond what these surfaces declare.
