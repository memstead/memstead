An agent talks to Memstead over MCP. A write is a `memstead_create` (or `memstead_update`) call naming a mem, an entity type, a title, sections, metadata and optional relations; the handler checks the note, resolves role and identity, takes the single engine lock and passes the call to the engine (memstead-mcp/src/server.rs `memstead_create`; memstead-mcp/src/lib.rs `lock_engine!`).

The engine first compares the mem's current head with its cached head and reloads if another writer advanced it (memstead-base/src/engine/drift.rs `reload_if_stale`). Then a fixed chain of refusals runs before any byte is written: the mount must be writable; the type must exist in the mem's pinned schema; section keys, reserved metadata keys, typed and enum field values, anchors and embedded headings are validated; the title becomes a slug and id, and a non-stub duplicate refuses; missing required sections or fields refuse with recovery payloads; each inline relation passes the same gates as `memstead_relate` (target grammar, cross-mem policy, rel-type vocabulary and shape, acyclicity); wiki-links without a backing relation refuse; then the markdown is rendered and block-tier format, required-outgoing and constraint checks run, warn-tier ones becoming warnings (memstead-base/src/engine/mutation/create.rs `prepare_create`; mutation/mod.rs `render_for_write`). A `dry_run` stops here and returns the prospective hash.

The file is YAML frontmatter, `# title`, one `## heading` per section and a `## Relationships` list of `[[wiki-links]]` (memstead-base/src/entity/generator.rs `generate_markdown`). For a git-branch mem the backend stages it, then `commit` writes a blob, edits the parent tree and creates one commit on the mem's branch, author derived from the client, trailers for Tool, Actor, Client, Role, Identity and note; if the ref moved meanwhile the commit fails as a hash mismatch instead of rebasing, and a checked-out worktree is synced with `git read-tree` (memstead-git-branch/src/storage/git_tree.rs `commit`, `sync_index_and_worktree`; memstead-base/src/vcs.rs `format_commit_message`). A plain folder mem writes the file atomically and appends a JSONL changelog; no git commit happens there (memstead-base/src/storage/filesystem.rs `commit`, `append_provenance`).

After the commit the engine re-parses what it wrote, upserts the entity into its in-memory store, auto-stubs missing relation targets, refreshes search indexes and records the new head as its own write (create.rs `commit_prepared_create`). The agent gets back id, file_path, `_hash`, `write_id` (the commit SHA), warnings, type_guidance, incoming edges and `durable`/`durability_basis` (server.rs `attach_durability`). Later it reads the entity as markdown with `_hash` in the frontmatter via `memstead_entity`, sends that hash as `expected_hash` on update for optimistic locking, and lists what moved with `memstead_changes_since` (server.rs; update.rs).
